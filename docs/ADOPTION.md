# 采用与升级

先阅读 [可独立交给 dot 的 Cookbook](../template/COOKBOOK.md)。只想开始任务时不必先安装全部模板。

中文与英文采用指南均指向同一套 `template/` 中英对照共享模板。每个字段只有一个含义与取值；保持两语言表达一致，不重复采用两套规则。

当前 workflow 版本为 v2.1。规则文件名仍为 `template/docs/workflow-v2.md`，版本以文件标题和文末「变更记录」为准。

## 首次采用
1. 若有已核验的发布 tag，记录 tag 及完整 commit；没有 tag 时固定完整 commit，并注明未发布。不要依赖可移动的 main。
2. 仅复制 `template/` 所需文件到项目，不复制 private-context 或本仓历史。
3. 将 `AGENTS.md.template` 保存为项目 AGENTS.md；将 PR 模板放入目标平台认可的位置（例如 `.github/pull_request_template.md` 或 `.gitea/pull_request_template.md`），采用前验证平台支持。
4. 填写项目命令、测试路径、独立评审机制、编码工具与档位、技术研究角色、署名 trailer 来源、required checks、发布边界与合并策略。workflow 中的默认工具与模型可在适配表覆盖。以下两项项目没有配置时不写“未配置”，而是填默认做法：
   - 技术研究角色：由负责编程的 agent 自己查官方文档，并附上来源链接。
   - 署名 trailer 来源：没有署名脚本或策略文件时，按编码 agent 的运行环境另加来源 trailer。云端运行（例如 Codex 云端）只写工具标识，如 `Code-Tool: codex <模型> <档位>`，不写 Host-Id；本地电脑运行写同样的工具标识并加 `Host-Id: <host-id>`。文档只用占位符，不写真实主机名。采用前须知：本地运行时 host id 会出现在公开的提交记录里。

   其余不存在的检查写“未配置”，不得写已通过。
5. 项目通过自身的评审和批准后合入，记录模板来源版本；复制文件不等于部署流程生效。
6. 先用小任务验证：失败复现 → 实现 → 回归 → 独立评审 → 精确 SHA 检查。发布/部署另按项目授权。

## 可配置与不可混淆
- GitHub/Gitea 的审批、保护、检查和评审 App 能力不同，不能直接假定等价。
- 不默认安装 App、创建 token、改权限或 required checks。
- 保留原提交的 fast-forward 是可选策略，不是所有项目默认；不满足保护要求就停止，不换绕过方式。
- 纯文档变更可注明行为测试不适用并解释原因，不伪造红绿证据。
- 私有 staging 也不应混入私人协调；发布使用项目自己的显式白名单与隐私检查，不带私人历史。

## 升级与回退
升级用独立 PR 对比两个已固定 commit（如有则附 tag），只搬运适用规则，记录冲突和采纳原因。回退通过新的 revert 提交恢复上一已核验版本，不强推或删除历史。模板版本与项目采用版本分别记录；维护本仓不自动更新各项目。

从 v2 升级到 v2.1 时，另外核对以下几点：
- 适配表新增的三行（编码工具与档位、技术研究角色、署名 trailer 来源）是否已填写；后两项没有配置时，是否已按默认做法填写。
- 在本地电脑运行并采用 Host-Id trailer 前，是否知悉 host id 会出现在公开的提交记录里。
- 默认分工是否适用于本项目；不适用就在适配表覆盖。
- 停止点清单、扫描与推送分离等新增规则是否与项目已有门禁冲突；有冲突先确认，不静默替换。

## 版本约定
0.x 表示仍需在项目适配验证。补丁版本修正文案；次版本增加兼容模板；不兼容流程变更在稳定版本后提升主版本。发布版本附 CHANGELOG 与 Git tag；开发中的未发布变更记为 Unreleased，不提前宣称已发布。

模板仓版本（如 0.2.0）与 workflow 版本（如 v2.1）分别编号：前者标识整套模板的发布，后者标识 workflow 规则本身，写在 `workflow-v2.md` 的标题和文末变更记录中。
